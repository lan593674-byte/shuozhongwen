# 说中文

用户输入 `/shuozhongwen`，后面跟题目或稿件，就按下面的流程写或改一篇中文文章。目标三件事同时做到：**事实不动、没有 AI 腔、写得好**。

文章写得差，多半不是句子的毛病，是动笔时手里没东西：没有具体的素材，没想清楚这篇要让读者得到什么，只好拿套话和套路把篇幅撑起来。所以这套流程先备料、列提纲，再写初稿；写完再查套路，再请全新的评委挑毛病，按证据改到过线为止。写初稿时把注意力放在内容上，套路检查放到写完以后。

插件根目录 `R` = `${CLAUDE_SKILL_DIR}/../..`（Claude Code 会自动换成实际路径；其他 agent 用 `install.py` 安装时会写成绝对路径），脚本在 `R/scripts`（下称 `S`）。Python 用 `python3 -X utf8`（Windows 上是 `python -X utf8`），需要 3.10 以上，核心脚本只用标准库。规则细则都在 `references/`，用到哪篇读哪篇，不用一次全读。

## 先看参数

- 第一个参数是 `lunwen`（如 `/shuozhongwen lunwen 报告.docx`，也可以用单独的命令 `/shuozhongwen:lunwen 报告.docx`）：论文特化。读 `references/lunwen.md`，按那里的流程走，**下面的流程不用**。学术论文、毕业论文、课程设计报告、实验报告、综述，用户没写 `lunwen` 你也认出来了，先问一句要不要改用论文模式。
- 第一个参数是 `qingli`（如 `/shuozhongwen qingli 报告.docx`，也可以用单独的命令 `/shuozhongwen:qingli`）：检测并清除零宽字符等不可见字符和乱码。读 `R/skills/qingli/SKILL.md`，按那里的步骤做，**下面的流程不用**。
- 其他情况：按下面的流程走。

先分清是哪种活，后面几步按它走：

- **改稿**：用户给了一份稿子让你改。
- **根据材料新写**：用户给了材料（笔记、数据、报告、采访、聊天记录、网页摘录……），让你据此写一篇新的。
- **只给题目**：用户只给了题目或要求，没有任何材料。

**改稿和根据材料新写**，动笔前先加载数据保真约束 `baozhen`：Claude Code 里调用技能 `shuozhongwen:baozhen`，其他 agent 读 `R/skills/baozhen/SKILL.md`。它全程生效，优先于本页的一切目标：原稿或材料里的数字、表格、引用、术语、论断强度，用到的一个都不改，材料没有的不补，看起来错了也只列给作者。拿不准算哪种，就当要加载。

**没有 Python**（`python`、`python3`、`py` 都跑不起来）：告诉用户下面的检查脚本需要 Python 3.10 以上，请用户自己装或同意你来装（Windows：`winget install Python.Python.3.12`；macOS：`brew install python`）。用户不装，就跳过脚本那几步，在修改报告里写明“未跑脚本检查”，证据核对改为你逐条手工核对。不要自己把脚本改写成别的语言来代替。

## 流程

**1. 认文体，定标准**

- 实用文本（周报、通知、方案、说明、答复、技术文档）：准确、简洁、具体。可以看 `references/before-after-worktext.md` 里从 AI 稿改到人话的动作。
- 议论文字（评论、网络问答、观点文章）：观点立得住、论证具体、有人在说话。读 `references/craft.md` 的「发现」「声音」。
- 文学性文字（散文、游记、随笔、小说、演讲、书评影评）：写得好。读 `references/craft.md`。

文体照题目要你做的事来定：题目让你介绍、说明、对比、概述，就是说明文，按实用文本的标准写和审；题目明确要你论证一个观点、表明立场，才算议论。不要自己把说明文升格成议论文，再去补立场。拿不准就问：读者读完要知道一件事（实用），同意一个看法（议论），还是看见、感到一些东西（文学）。文体要写具体，比如“课程论坛帖（说明文）”“城市随笔散文”，后面审读按它定标准。

**2. 写前准备：任务、素材、提纲**

这一步决定初稿的好坏，不能省。下面三样写在工作区或回复里，不进正文。

- **任务**：用一两句话复述用户要什么：写给谁看，题目要你做哪几件事（介绍什么、对比什么、要不要表态），字数和格式。用户没说字数，就按这种文体常见的篇幅，宁短勿长。格式里包括这种文体本来就带的部分：论坛帖、文章、新闻稿要标题，书信要称呼和落款，通知要时间、地点和对象；用户没说不要，就照惯例带上。这句复述第 5 步要交给评委。
- **素材**：
  - 改稿、根据材料新写：按 `baozhen` 先列数据清单，再从里面挑出最具体、最能说明问题的几条（数字、动作、实物、原话），文章就靠它们立起来。原稿或材料没有的细节、经历、引语、数字、判断一律不补，缺了列进“建议作者补充的细节”；材料里看起来有错或互相矛盾的，列进“待作者核对”。
  - 只给题目：先找素材再写。手头有搜索或联网工具，就去查，把要用的事实连同来源列出来；查不到、记不准的不用。没法联网，就只用你确定的常识，并在修改报告里写明“未联网核对”。
  - 要靠作者亲身经历的文字（游记、回忆、随笔、个人陈述、发言稿……），用户又没给经历：先别写，一次问用户三到五个具体问题，比如什么时候去的、印象最深的一个画面、一件出乎意料的小事、喜欢还是失望。拿到回答再写。用户不想答，就写成不依赖亲身经历的介绍或评论，并在报告里说明；不编“我”的经历。
- **写什么，按什么顺序写**：用一句话写出读者读完要知道、同意或看见的那件事（文学和议论文字里这就是“发现”，说明和实用文本里就是这篇要讲清的核心）。再列提纲，一段一行，每行先写这段开头用的那件事（一个数字、一个动作、一个场面、一条材料），再写它说明什么，比如“Uswitch 调查：18 到 34 岁四分之一从不接电话，37% 更喜欢语音 → 躲的是电话这种形式”。不要把提纲写成一串论点（“年轻人并不怕开口”“来电者变了”）：提纲里的论点会原样变成每段的第一句，段首短判断就是这么来的。素材撑不起提纲，回去补素材或问用户，不要靠写法凑。
- **说明文和实用文本，提纲排完对着任务再查两件事**：任务问的核心问题（三处工程怎样配合、节气怎么定出来）有没有一段正面回答；讲经过、原理、历史的，时间链和因果链中间有没有断档，漏掉的一环补上。取舍删的是枝节，不是主干上的环节。
- **篇幅**：估一下手里的素材能写多长。改稿和根据材料新写时，素材明显撑不起用户要的篇幅（比如笔记里只有三百字的事，要写一千字），先告诉用户、请他补素材；用户不在或不补，就按素材能撑起的篇幅写，不凑字，在修改报告第一条写明差多少、缺什么，交给评委的任务里照实写上这一点。

**3. 写初稿**

照提纲整篇写，从含义出发，别逐句翻译。

- 第一句就进入题目本身。不写“下面介绍……”“本文将……”“以下内容出自……”这类开场白，也不在正文里交代你手头的资料（“材料里只有两条”“课程没有讲”）；资料覆盖不到的地方就不写，缺口放进修改报告。说明文可以先用一句以题材本身为主语的话交代全貌，比如“江水从上往下，依次经过鱼嘴、飞沙堰和宝瓶口三处工程。”，这是内容，读者靠它看清后面的顺序；“下面介绍三处工程”才是报幕。
- 一段写一件事。每段第一句写一件具体的事（人、物、时间、地点、数字、动作），判断跟在事实后面；有的段落只摆事实也可以。不要用一句十来个字的结论开头再展开，这是模型写中文最常见的段落套路，评委会把它算作模板腔。比如“可太阳走得并不匀。”这样开头的段落，改成先摆事实：“冬至到小寒只有 14.7 天，夏至到小暑却有 15.7 天。”
- 用素材里最具体的那几条。想让读者停下来的地方写足，其余一笔带过，别把所有事实压成一张清单。
- 用准确的普通词，同一样东西从头到尾一个叫法。句子长短跟着内容走，一件事说完就收。
- 出处非必要不写，事实直接写明。“课上讲过”“老师说过”“资料显示”这类话，只有出处本身对论证有用时才留（比如要区分是谁的说法）。用户明确要求标注出处、参考文献的，按要求标。
- 引号留给整句的原话：材料、采访、文献里谁说的哪句话。词和短语一般不加引号，只有需要标出的专名、被拿来当词本身讨论的词例外。不要给自己概括出来的说法、强调的词、口语说法加引号（“上瘾模型”“参考地图”“一点点”），这是 AI 文字最扎眼的地方：人类文字里引号多半引整句，AI 的引号多半套在词上。要表示“所谓”，就写“所谓”两个字。改别人的稿子时，原稿里的引号属于原文，按 `baozhen` 保留。
- 说明、介绍类的文字不用“我”，直接把事情讲清楚；题目要求表态、或者不用“我”就说不清时才用。无论用不用，都不要把你自己的操作过程写成作者的经历（“这一讲我读得最久”“短片我没找到字幕”），作者真实的体会只能来自材料或用户本人。
- 结尾停在最后一件实事、一个画面或一句克制的话上，不总结、不号召。这件事要落在题目的核心问题上：说明文收在核心问题的最后一环，议论收在立场和它的代价上，小说散文收在主线的画面上。不要临到结尾另起一个新话题（换个地方的气温、另一所学校的课），读者会觉得没写完。
- 文学性文字按 `references/craft.md` 的五根柱子写：具体、发现、语言、节奏与结构、声音。
- 第 2 步定下要标题的，标题按 `references/rules.md` 的「标题红线」起：平实直给，是什么就写什么。
- 改稿：先读懂全篇，按第 2 步的提纲整段改写，不要逐句去顺。改法细则见 `references/rules.md` 和 `references/symptom-dictionary.md`。删掉的套话和修饰，要换成具体细节，不能只删不补。

**4. 写完自查**

初稿写进文件，先跑机器扫描：

```
python S/polish_check.py 稿件
```

它查不可见字符、四条机械扫描（章节编号、元话语、半角标点、“不是 X 而是 Y”超过两处）、结构套路和 AI 相似度。结构套路里，段首短判断句成串、总结翻转套话（“说到底”“回头看”“不只是……也……”）、同一出处反复引述、开场白和资料交代，以及四类以上套路叠加，都要改到通过。

标“提示”的几项（设问自答、单句成段、冒号清单、段尾对仗警句、前后回扣、给普通词打引号、第一人称过程交代）不拦交付，但要逐处看。其中前五样是正常的写作手法，名家文章里也有：用一次、用得自然就留着；同一种手法在一篇里出现两次以上，多半是在拿它搭架子，改掉。后两样按第 3 步的规矩改。脚本还会列出第一句很短的段落，逐个看：是结论、判断或报幕的，按第 3 步改成从事实写起。脚本还会列出每一处套在词和短语上的引号，逐处做去引号测试：去掉引号再读一遍，意思不变就去掉。

AI 相似度只是护栏，落在人类常见区间就够了，**不往下压**。落在 high 时，按列出的项目用写得更好的办法改（补细节、删套话、调节奏），不要为了压分重复用词、乱加标点。

然后对着提纲回读一遍：每段都在写它该写的事吗？改稿和根据材料新写时，按 `baozhen` 拿数据清单逐条对回去。

**5. 编辑审读和事实核查（外部模型或全新子代理）**

**优先用外部模型当评委。** 写稿的模型给自己打分会偏松：它认不出自己的套路，还会把它们当成好文章。插件带了一个 MCP 服务（工具名里有 `shuozhongwen` 和 `judge`），用 `judge_status` 看看配置了没有：

- 配置了：调用 `judge`（参数：文体 `genre`、任务 `task`（第 2 步复述的那句）、稿件路径 `path` 或全文 `text`）和 `factcheck`（参数：`path` 或 `text`；只给题目的稿子加 `own: true`），两个可以同时调。每次都是一次全新的请求，只带评分标准和正文。工具返回的结论已经按 `review_zh.py` 核对过；把其中的原始 JSON 存成文件，交稿前的复审照样用 `review_zh.py`。
- 没配置或调用失败：告诉用户可以用 `python S/judge_config.py set --base 接口地址 --model 模型名 --key-env 环境变量名` 配一个（任何兼容 OpenAI 接口的模型都行），这一轮先按下面的子代理做。

用子代理时：

把稿子写进文件，然后在同一条消息里并行调用两个子代理。它们都是当前会话模型的全新实例，不带这次会话的任何上下文、CLAUDE.md 和技能，只看到你给的内容：

- 评委：子代理类型 `shuozhongwen:judge`，提示只写下面三样，不加任何说明、背景、改稿经过或作者信息：

  ```
  文体：课程论坛帖（说明文）

  任务：介绍亚北极地区的普遍描述，再说明它放到詹姆斯湾的克里人身上对不对得上，500 字左右，只用课程材料

  正文：
  <<<
  （完整正文）
  >>>
  ```

  任务就是第 2 步复述的那一两句，只写用户要什么，不写你怎么写的。

- 事实核查：子代理类型 `shuozhongwen:factcheck`，提示只写 `正文：` 加完整正文，**必须是全文**，不许只摘你想查的句子。实用文本里没有可核查的事实时，可以跳过这一步。

不在 Claude Code 里（没有 `shuozhongwen:judge` 这类子代理）时，任选一种，要求不变：评委每次都是全新的，只看到评分标准、文体、任务和正文。

- 你的 agent 能开子代理（Codex、Cursor 等）：开一个全新的子代理，把 `R/agents/judge.md` 分隔线以下的内容当评分标准，后面接上面那段“文体 + 任务 + 正文”；事实核查同理，用 `R/agents/factcheck.md`。不给子代理任何别的上下文。
- 用任意兼容 OpenAI 接口的模型当评委（也可以特意换一个和写作者不同的模型，减少自我偏好）：`python S/judge_api.py 稿件 --genre 课程论坛帖（说明文） --task "任务原话"`，接口和模型用 `judge_config.py` 配，或者用环境变量 `SHUOZHONGWEN_MODEL`、`SHUOZHONGWEN_API_BASE`、`SHUOZHONGWEN_API_KEY`。它把 JSON 存在稿件旁边，并直接给出下面 `review_zh.py` 的核对结果。
- 两样都没有：请用户在一个全新的对话里贴评分标准和正文，把返回的 JSON 交给你。不要在当前会话里自己给自己打分冒充审读。

把两个子代理返回的 JSON 原样存成文件，然后跑：

```
python S/review_zh.py 稿件 --genre 课程论坛帖（说明文） --review 审读.json --facts 核查.json
```

只给题目、没有材料的稿子加 `--own`；改稿和根据材料新写都不加。脚本逐项核对评委给的证据是不是原文原句，引不出原文的那一项作废，只要有作废项，这轮审读无效，换一个全新的评委重审。

通过条件：文学性文字平均 ≥ 4、每项 ≥ 3；实用和议论文字平均 ≥ 3.5、每项 ≥ 3；不是白开水；没有偏题（只因篇幅判偏题、第 2 步又已写明素材不够的，见第 6 步，只提示不拦）；评委认出的模板腔最多 1 处（零容忍试过：评委每次随机挑出不同的一处，几乎同一篇稿子三次评出 3.5、3.17、2.83，所以放宽到 1 处）。评委列在“手法重复”里的设问、单句成段这类，只提醒，不算未通过。

事实存疑：只给题目的稿子要改到 0；改稿和根据材料新写的，不算未通过，凡是来自原稿或材料的存疑项全部列进“待作者核对”，正文不动。（根据材料新写时，如果存疑的是你自己加的、材料里没有的说法，那本来就违反了 `baozhen`，删掉。）事实核查子代理会记错，它给的“正确数字”不能直接用：只给题目的稿子，改之前要找到可靠来源；找不到就删掉那句或改成不含具体数字的说法。

**6. 按证据改**

没过，就按脚本列出的最弱两项和评委的改法改：

- 先看评委引的证据是不是真问题。评委也会错（比如把本来成立的数学关系说成矛盾），照改之前先核对。
- 问题出在哪一段，就回到提纲把那一段重写，不要在原句上打补丁。补丁摞补丁，文章会越改越散。
- 只因篇幅不够判了偏题（评委写的是“篇幅”），而素材确实撑不起、第 2 步也写明了：不凑字。复审时给审读加上素材不足的标记（`review_zh.py` 和 `judge_api.py` 加 `--short-material`，MCP 的 `judge` 工具传 `short_material: true`），篇幅就只提示、不拦交付；修改报告第一条写明差多少、缺什么。评委写的是“内容”，就是真偏题，照改。
- 评委说缺细节、缺发现、缺声音，而素材里确实没有：不编，也不要硬造判断句、警句、设问来充数，那正是模板腔。改稿和根据材料新写时，列进“建议作者补充的细节”；只给题目的，回第 2 步补查素材，或者问用户。
- 事实存疑的：只给题目的稿子，找到来源后改正，找不到就删；来自原稿或材料的，一律不改，列给作者。

改完回第 4 步自查，再回第 5 步，**每一轮都用全新的评委**，不要把上一轮的评语、分数或“这是修改稿”告诉新评委。过了就停，不为刷分再改；文学性文字过了以后，再做第 7 步的一轮精修。改三轮还过不了，停下来告诉用户卡在哪一项、缺的是什么素材。

**7. 精修（只对文学性文字，只做一轮）**

评委的打分到了好稿就饱和：两篇稿子都过线、都接近满分，放在一起看，高下还是很明显。所以文学性文字过线以后再改一轮，让新旧两稿正面比一次：

- 原稿留着，在副本上改：按评委给的最低一两项的改法改；把素材里还没用上的具体细节补进去，让前面出现的东西后面有着落；删掉替读者解释人物想法、语气、用意的句子（“听口气没有抬杠的意思”“她心里其实很感激”），让动作和对话自己说。根据材料、笔记写的，补的细节只能来自材料（`baozhen`）；只给题目的小说可以新写细节。
- 新稿跑第 4 步的 `polish_check.py`，要通过。
- 盲评对比：把两稿交给全新的对比评委，A、B 两种顺序各问一次，评委不知道哪篇是新稿。外部模型：`python S/judge_api.py 新稿 --compare 原稿 --genre 文体 --task "任务"`，或 MCP 的 `compare` 工具（`path` 是新稿，`baseline_path` 是原稿）；子代理：两个 `shuozhongwen:compare` 在同一条消息里并行调用，一个把原稿放 A、新稿放 B，另一个反过来，提示只写文体、任务、稿子 A、稿子 B；其他能开子代理的 agent，用 `R/agents/compare.md` 分隔线以下的内容当标准，同样两种顺序各开一个。两次都判新稿更好，才往下走；否则交原稿。
- 新稿再走一次第 5 步（全新评委和事实核查）。过了交新稿，没过交原稿。修改报告里写明精修结果：对比评委两次怎么判的，交的是哪一稿。

**8. 交稿**

交稿前最后跑一次 `polish_check.py`，结论要是“通过”。

先给正文；正文后面单起一行写 `【修改报告】`，再写报告（模板见 `references/workflow.md`）：文体、任务、主线、数据核对（改稿和根据材料新写时，按 `baozhen`）、编辑审读的分数和照改的意见、事实核查结果、待作者核对、建议作者补充的细节、硬闸结果。回复末尾的 AI 相似度只算 `【修改报告】` 前面的正文；它只说明统计信号，不等于能通过哪家检测器。
