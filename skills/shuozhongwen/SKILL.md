# 说中文

用户输入 `/shuozhongwen`，后面跟题目或稿件，就按下面的流程写或改一篇中文文章。目标三件事同时做到：**事实不动、没有 AI 腔、写得好**。文章写得差，多半是动笔时手里没东西，只好拿套话撑篇幅；所以先备料、列提纲再写，写完查套路，再请全新的评委挑毛病，按证据改到过线。

插件根目录 `R` = `${CLAUDE_SKILL_DIR}/../..`（其他 agent 用 `install.py` 安装时会写成绝对路径），脚本在 `R/scripts`（下称 `S`）。Python 用 `python3 -X utf8`（Windows 是 `python -X utf8`），3.10 以上。细则在 `references/`，用到哪篇读哪篇。

## 先看参数

- `lunwen`（或 `/shuozhongwen:lunwen`）：论文特化，读 `references/lunwen.md`，不走下面的流程。用户没写 `lunwen`，但稿子是论文、课程设计报告、实验报告、综述，先问一句要不要用论文模式。
- `qingli`（或 `/shuozhongwen:qingli`）：清除零宽字符和乱码，读 `R/skills/qingli/SKILL.md`，不走下面的流程。
- 其他：按下面的流程走。先分清是**改稿**、**根据材料新写**（用户给了笔记、数据、采访、网页摘录等）还是**只给题目**。

改稿和根据材料新写，动笔前先加载数据保真约束 `baozhen`（Claude Code 里调用技能 `shuozhongwen:baozhen`，其他 agent 读 `R/skills/baozhen/SKILL.md`）。它优先于本页一切目标：原稿或材料里的数字、引用、术语、论断强度，用到的一个都不改，材料没有的不补，看起来错了也只列给作者。拿不准算哪种，就当要加载。

没有 Python 时，告诉用户检查脚本需要 Python 3.10 以上（Windows：`winget install Python.Python.3.12`；macOS：`brew install python`）。用户不装，就跳过脚本，在修改报告里写明“未跑脚本检查”，证据逐条手工核对；不要把脚本改写成别的语言。

## 流程

**1. 认文体，定标准**

- 实用文本（周报、通知、方案、说明、答复、技术文档）：准确、简洁、具体。可参考 `references/before-after-worktext.md`。
- 议论文字（评论、网络问答、观点文章）：观点立得住、论证具体、有人在说话。读 `references/craft.md` 的「发现」「声音」。
- 文学性文字（散文、游记、随笔、小说、演讲、书评影评）：写得好。读 `references/craft.md`。

文体照题目要你做的事来定：介绍、说明、对比、概述是说明文，按实用文本写和审；明确要论证观点、表明立场才算议论，不要把说明文升格成议论文。文体写具体，比如“课程论坛帖（说明文）”，审读按它定标准。

**2. 写前准备：任务、素材、提纲**（写在工作区，不进正文）

- **任务**：一两句话复述用户要什么：写给谁看，要做哪几件事，字数和格式。没说字数就按这种文体常见的篇幅，宁短勿长；说了上限，初稿就按上限以内写。格式包括文体本来就带的部分：论坛帖、文章、新闻稿要标题，书信要称呼和落款，通知要时间、地点和对象。这句复述第 5 步要交给评委。
- **素材**：
  - 改稿、根据材料新写：按 `baozhen` 列数据清单，从中挑出最具体、最能说明问题的几条。材料没有的不补，缺的列进“建议作者补充的细节”，看起来有错的列进“待作者核对”。
  - 只给题目：先查再写，把要用的事实连同来源列出来，查不到、记不准的不用；没法联网就只用确定的常识，报告里写明“未联网核对”。
  - 要靠作者亲身经历的文字（游记、回忆、个人陈述……）而用户没给经历：先一次问三到五个具体问题（什么时候、印象最深的画面、意外的小事、喜欢还是失望），拿到回答再写。用户不答，就写成不依赖亲身经历的介绍或评论；不编“我”的经历。
- **提纲**：先用一句话写出读者读完要知道、同意或看见的那件事（文学和议论里就是“发现”）。再一段一行列提纲，每行先写这段开头用的那件事（数字、动作、场面、材料），再写它说明什么。提纲不要写成一串论点，论点会原样变成每段第一句的短判断。素材撑不起提纲，回去补素材或问用户，不靠写法凑。
- 说明文和实用文本，提纲排完对着任务查两件事：核心问题有没有一段正面回答；讲经过、原理、历史的，时间链和因果链有没有断档。取舍删枝节，不删主干上的环节。
- **篇幅**：素材明显撑不起用户要的篇幅（笔记里只有三百字的事，要写一千字），先请用户补素材；用户不在或不补，就按素材能撑起的长度写，不凑字，报告第一条和交给评委的任务里都照实写明。

**3. 写初稿**

照提纲整篇写，从含义出发，别逐句翻译。

- 第一句就进入题目。不写“下面介绍……”“本文将……”这类开场白，不在正文里交代手头的资料（“材料里只有两条”）；资料覆盖不到的不写，缺口放进报告。说明文可以先用一句以题材本身为主语的话交代全貌（“江水从上往下，依次经过鱼嘴、飞沙堰和宝瓶口三处工程。”），这是内容，不是报幕。
- 一段写一件事，第一句写一件具体的事，判断跟在后面。不要用一句十来个字的结论开段再展开（“可太阳走得并不匀。”），评委算模板腔；改成先摆事实（“冬至到小寒只有 14.7 天，夏至到小暑却有 15.7 天。”）。
- 用最具体的那几条素材，想让读者停下来的地方写足，其余一笔带过，别压成清单。用准确的普通词，同一样东西一个叫法；句子长短跟着内容走。
- 出处非必要不写，事实直接写明；“课上讲过”“资料显示”只在出处本身对论证有用时留。用户要求标注出处的照标。
- 引号只给整句原话、需要标出的专名、被当作词本身讨论的词。不给自己的概括、强调的词、口语说法加引号（“上瘾模型”“一点点”）；要表示“所谓”就写“所谓”。改稿时原稿的引号按 `baozhen` 保留。
- 说明、介绍类不用“我”，题目要求表态或不用就说不清时才用；不把自己的操作过程写成作者的经历（“这一讲我读得最久”）。
- 结尾停在一件实事、一个画面或一句克制的话上，不总结、不号召，而且落在题目的核心问题上：说明文收在核心问题的最后一环，议论收在立场和它的代价上，小说散文收在主线的画面上。不在结尾另起新话题。
- 文学性文字按 `references/craft.md` 的五根柱子写。标题按 `references/rules.md` 的「标题红线」：平实直给。
- 改稿：先读懂全篇，按提纲整段改写，不逐句去顺；删掉的套话要换成具体细节。细则见 `references/rules.md`、`references/symptom-dictionary.md`。

**4. 写完自查**

初稿写进文件，跑 `python S/polish_check.py 稿件`。它查不可见字符、四条机械扫描（章节编号、元话语、半角标点、“不是 X 而是 Y”超过两处）、结构套路和 AI 相似度。段首短判断成串、总结翻转（“说到底”“回头看”）、同一出处反复引述、开场白和资料交代、四类以上套路叠加，都要改到通过。

标“提示”的几项不拦交付，但逐处看：设问自答、单句成段、冒号清单、段尾对仗警句、前后回扣是正常手法，用一次、用得自然就留，同一种用两次以上多半在搭架子；给普通词打引号、第一人称过程交代按第 3 步改。脚本列出的短首句段落，是结论或报幕的改成从事实写起；列出的词语引号，去掉再读，意思不变就去掉。

AI 相似度只是护栏，落在人类常见区间就够，**不往下压**；落在 high 时补细节、删套话、调节奏，不为压分重复用词、乱加标点。最后对着提纲回读，改稿和根据材料新写时拿数据清单逐条对回去。

**5. 编辑审读和事实核查**

写稿的模型给自己打分偏松，**优先用外部模型当评委**：插件的 MCP 服务（工具名含 `shuozhongwen`、`judge`）先用 `judge_status` 看配置。配置了就同时调 `judge`（`genre`、`task`（第 2 步的复述）、`path` 或 `text`）和 `factcheck`（`path` 或 `text`；只给题目加 `own: true`），返回结论已按 `review_zh.py` 核对，原始 JSON 存成文件备复审。没配置就告诉用户可以 `python S/judge_config.py set --base 接口地址 --model 模型名 --key-env 环境变量名` 配一个，这一轮用子代理。

子代理：把稿子写进文件，同一条消息里并行调用两个（全新实例，不带本会话上下文）：

- `shuozhongwen:judge`：提示只写“文体：…”“任务：…”“正文：<<< 全文 >>>”三样，不写背景、改稿经过、作者信息。任务只写用户要什么。
- `shuozhongwen:factcheck`：提示只写“正文：”加**全文**，不许只摘句子。实用文本没有可核查的事实时可跳过。

不在 Claude Code 里：能开子代理的 agent，用 `R/agents/judge.md`、`R/agents/factcheck.md` 分隔线以下的内容当标准开全新子代理；或用任意 OpenAI 兼容模型 `python S/judge_api.py 稿件 --genre 文体 --task "任务"`（`judge_config.py` 配，或环境变量 `SHUOZHONGWEN_MODEL`、`SHUOZHONGWEN_API_BASE`、`SHUOZHONGWEN_API_KEY`），它直接给出核对结果。都没有，就请用户在全新对话里贴标准和正文，把 JSON 交给你。不要自己给自己打分冒充审读。

子代理返回的 JSON 原样存文件，跑 `python S/review_zh.py 稿件 --genre 文体 --review 审读.json --facts 核查.json`（只给题目加 `--own`）。评委的证据引不出原文，那一项作废，这轮审读无效，换全新评委重审。

通过条件：文学性文字平均 ≥ 4、每项 ≥ 3；实用和议论文字平均 ≥ 3.5、每项 ≥ 3；不是白开水；没有偏题（只因篇幅、且素材确实不够的见第 6 步）；评委认出的模板腔最多 1 处（零容忍时同一篇稿子三次评出 3.5、3.17、2.83，所以放宽）。“手法重复”只提醒。

事实存疑：只给题目的稿子改到 0，核查子代理给的“正确数字”要找到可靠来源才用，找不到就删掉那句或去掉具体数字；改稿和根据材料新写的，来自原稿或材料的存疑项列进“待作者核对”，正文不动，你自己加的材料外说法本就违反 `baozhen`，删掉。

**6. 按证据改**

没过，按脚本列出的最弱两项和评委的改法改：

- 先核对评委引的证据是不是真问题，评委也会错。
- 问题在哪一段，就回到提纲重写那一段，不在原句上打补丁。
- 只因篇幅判偏题（评委写“篇幅”）而素材确实不够：不凑字，复审加 `--short-material`（`review_zh.py`、`judge_api.py`；MCP 传 `short_material: true`），篇幅只提示不拦，报告第一条写明差多少、缺什么。评委写“内容”就是真偏题，照改。
- 缺细节、缺发现、缺声音而素材里没有：不编，不硬造判断句、警句、设问充数。改稿和根据材料新写的列进“建议作者补充的细节”；只给题目的回第 2 步补查或问用户。
- 事实存疑按第 5 步处理。

改完回第 4、5 步，**每轮都用全新评委**，不告诉它上一轮的评语、分数或“这是修改稿”。过了就停，不为刷分再改（文学性文字接着做第 7 步）。三轮还过不了，告诉用户卡在哪一项、缺什么素材。

**7. 精修（只对文学性文字，一轮）**

评委打分到好稿就饱和，两稿放在一起才看得出高下。所以过线后：

- 原稿留着，在副本上改：按评委最低一两项的改法改；补素材里还没用上的细节，让前面出现的东西后面有着落；删掉替读者解释人物想法、语气的句子（“听口气没有抬杠的意思”），让动作和对话自己说。根据材料写的，补的只能来自材料。新稿要过 `polish_check.py`。
- 盲评对比：两稿交给全新的对比评委，A、B 两种顺序各问一次。外部模型用 `python S/judge_api.py 新稿 --compare 原稿 --genre 文体 --task "任务"` 或 MCP 的 `compare`（`path` 新稿，`baseline_path` 原稿）；子代理用两个 `shuozhongwen:compare` 并行，一个原稿在 A，一个新稿在 A，提示只写文体、任务、稿子 A、稿子 B（其他 agent 用 `R/agents/compare.md` 当标准）。
- 两次都判新稿更好，新稿再走一次第 5 步，过了交新稿；否则交原稿。报告里写明对比结果和交的是哪一稿。

**8. 交稿**

最后跑一次 `polish_check.py`，结论要是“通过”。先给正文，后面单起一行 `【修改报告】` 写报告（模板见 `references/workflow.md`）：文体、任务、主线、数据核对、审读分数和照改的意见、事实核查、精修结果、待作者核对、建议作者补充的细节、硬闸结果。回复末尾的 AI 相似度只算正文，只说明统计信号，不等于能过哪家检测器。
