# 论文特化：/shuozhongwen lunwen

用于学术论文、毕业论文、课程设计报告、实验报告、文献综述这类学术文字。只改语言，去掉 AI 腔，研究本身一个字不动。普通 `/shuozhongwen` 的目标之一是“写得好”（具体、发现、声音），这些标准不适用于论文：论文不需要文采，更不能靠补细节、加观点来“写得好”。

用法：`/shuozhongwen lunwen 稿件路径`。支持 .docx、.md、.txt。

## 先加载两条约束

1. `baozhen`（数据保真）：全程生效。Claude Code 里调用技能 `shuozhongwen:baozhen`；其他 agent 读 `R/skills/baozhen/SKILL.md`。
2. `xueshu`（学术严谨性审查）：只在本模式用。Claude Code 里调用技能 `shuozhongwen:xueshu`；其他 agent 读 `R/skills/xueshu/SKILL.md`。

## 流程

**1. 读稿，列数据清单**

按 `baozhen` 列出原稿的数据清单。.docx 先抽出全文：`python S/doc_text.py 稿件.docx -o 原稿.txt`（段落和表格都在，表格一行一格用 ` | ` 隔开），表格内容也要读到。

同时标出**不许动的部分**，只读不改：封面和署名、分工表、所有表格和图、公式、代码、摘要里的数字、关键词、引用标注、参考文献、致谢。

**2. 只改语言**

在不许动的部分以外，逐句改掉 AI 腔，改法看 `rules.md` 的去 AI 味部分和 `symptom-dictionary.md`，但按论文的规矩来：

- 可以改：虚动词（“进行了……分析”→“分析了……”）、空泛修饰（“具有重要意义”“起到了关键作用”）、机械衔接（“首先……其次……此外……综上所述”）、每段同一句式开头、段末总结拔高、同一段话在摘要、引言、结论里原样重复三遍。
- 保持学术语体：不口语化（不写“票房盘子越大”“换了条路”），不加比喻，不加感叹，不改人称（原稿用“本文”“本研究”就保留，最多把过密的地方换成无主句，不改成“我们”“我”）。
- 章节编号、图表编号、公式编号是学术规范，保留；机械扫描的“章节序号”一条在本模式不适用。
- 不动结构：不合并、拆分、删除段落，不调顺序，不新建表格，不补空表，不删图表。原稿的表格如果是空的，列进“待作者处理”。
- 减掉的只能是重复和空话，不能是信息。每删一个限定词、一个前提、一句局限，都是退步。

每一处改动都记进“修改对照表”：原句、改句、改了什么（去虚动词、删重复、调语序……）。作者要能逐条接受或拒绝。

**3. 数据核对**

按 `baozhen` 拿清单逐条对改稿。对不上的改回去。

**4. 语言审读 + 严谨性审查（外部模型或全新子代理，并行）**

优先用插件的 MCP 评委：`lunwen_judge`（文体 + 改稿）和 `rigor`（`original_path` 原稿 + `path` 改稿），先用 `judge_status` 看配置；没配置就用下面的子代理。

- 语言评委：子代理类型 `shuozhongwen:lunwen-judge`，提示只写“文体：（如 课程设计报告）”和改稿全文，格式同 SKILL.md 第 5 步的评委提示（论文模式不写任务那一行）。它只审语言，六项：表述准确、简洁、学术语体、衔接与逻辑、一致、去模板腔。
- 严谨性审查：子代理类型 `shuozhongwen:rigor`，给原稿和改稿全文，格式见 `xueshu`。
- 不跑普通模式的 `judge` 和 `factcheck`：前者按文学标准要“发现”“声音”，会把人往加内容的方向推；外部事实交给严谨性审查列给作者。

把两份 JSON 存成文件，然后跑：

```
python S/review_zh.py 改稿 --genre 课程设计报告 --paper --review 审读.json --original 原稿 --rigor 严谨.json
```

通过条件：语言六项平均 ≥ 3.5、每项 ≥ 3；严谨性退步为 0。其他 agent 可以用 `python S/judge_api.py 改稿 --genre 课程设计报告 --paper --original 原稿` 一次跑完这两项。

**5. 按证据改，改完换新子代理重审**

退步一律先处理：把那句改回原稿的意思和强度。语言项没过，按最弱项的改法改说法。评委的改法如果要求补内容、加结论、改数据，不照做，列进“待作者处理”。每一轮都用全新的子代理。过了就停；三轮还不过，停下来把卡住的项告诉用户。

**6. 过硬闸**

```
python S/polish_check.py 改稿 --paper
```

不可见字符为 0，元话语、半角标点、“不是 X 而是 Y”三条扫描都过（参考文献里的半角标点是著录规范，自动跳过），AI 相似度不在 high。AI 相似度只是护栏，技术文字本来就低，不要为了它改动任何内容。

**7. 交稿**

- 改稿：原稿是 .docx 就尽量交 .docx，在原文件的副本上替换段落文字，保留样式、表格、图片和编号；做不到就交纯文本，并说明需要作者粘回原文档。
- 修改报告，按顺序：
  1. 数据核对：清单共几条，全部对上（按 `baozhen`）
  2. 修改对照表：原句 → 改句 → 改了什么
  3. 语言审读：六项分数、照改的意见、没照改的意见及理由
  4. 学术严谨性审查（待作者处理）：原稿本身的问题，逐条列原句、问题、建议
  5. 待作者核对：看起来有误但按约束没改的数据和事实，附上你查到的来源
  6. 硬闸结果

## 反例

一份课程设计报告被普通模式改过一遍：背景数据被换成联网查到的新数字，“SVM”被写成“SVR”，“决定性影响”变成“影响最大”，“主要使用默认参数”变成“都用默认参数”，正文里的数字被整理成两张原稿没有的表，还加了“产出是一套可复现的流程，比多列几个模型名字有用”这种原稿没有的论断，语体也改成了“票房盘子越大”“机器学习换了条路”这样的口语。每一处都违反了本模式的规矩。
