# 写作交付的证据与验证

整合 verification 的可核验完成原则。保留 shuozhongwen 原有评审、数据保真和查 AI 率流程；本文件不引入新的脚本路径，也不把上游工具的启发式阈值当作论文合格标准。

## 完成声称的五步

先明确什么操作能证明声称，再实际执行，读取完整输出，判断它是否支持结论，然后报告状态与证据。代理报告、主观确信、部分检查、文件看起来完整都不能替代该步骤。检查失败时说明实际结果，修订后检查相关项。

| 准备声称 | 必须看到的证据 |
|---|---|
| 章节已生成 | 实际文件存在，内容对应本章，长度和结构符合已定要求 |
| 引用身份已核实 | DOI/原始出版记录或相应真实来源与作者、题名、年份一致 |
| 引用支持论点 | 实际读到的内容、证据映射、段落蓝图和支持范围对应 |
| 文献检索已完成本轮 | 数据库、检索式、日期、实际结果数与纳排/去重记录 |
| 格式已检查 | 对目标输出完成排版/结构检查；实际工具不可用时说明人工检查范围 |
| 数据保真通过 | 原文与改稿的数字、单位、对象、方法、事实、条件和边界核对通过 |
| 评审意见已处理 | 每项意见的修改位置与复核证据，未解决项明确 |
| 已查 AI 率 | 实际检测工具/版本或渠道、输入范围、时间和真实输出；没有检测就报告未检测 |
| LaTeX 可编译 | 实际编译成功与诊断，不能用文件生成或编辑器打开替代 |
| 稿件可定稿 | 适用内容、证据、数据、格式及占位问题均完成，范围和剩余限制明确 |

风格检查能发现某些模板表达，不证明“无 AI 痕迹”或特定 AI 率；人工判断不冒充外部检测。引用标记的数量也不证明引用真实或支持结论。

## 章节和证据复核

完整论文对照 `plan/chapter-architecture.md` 验收精确章文件、职责、实际长度、负责者记录与占位政策。主体不能只由标题、表格或摘要级短段构成；但不能用固定“每章六段/4500 字/五个引用”替代目标要求和内容判断。

依据 [evidence.md](evidence.md) 核对每个核心论点的支持、关键空白的证据组合、段落 citation slot 和阅读层级。既有文稿短段改写的验收对象是该段及其实际上下文，不借此强迫重做全篇。

## 结果与正文防污染

按 [results.md](results.md) 检查实验协议、贡献追踪、表格契约和结果数据清单，以及具体结果的真实来源、聚合和允许声称。模拟/规划条目不写为真实结果，投稿版本不能含未回填值或不明来源。

检查正文和附录无用户指令、回填指导、讨论提示和任务过程文字。计划内的未完成项不自动代表正文污染；对真正影响稿件定稿的缺口单独判断。表格和列表不能掩盖薄弱论证，压缩不丢证据、条件与限制。

## 规范合规、质量与最终报告

先复核任务包与体例：输出、章节、长度、格式、引用和用户约束。再复核质量：论证、语言、数据、支持范围与一致性。两阶段均通过后，中型任务把能力使用审计写入 `plan/progress.md`；详见 [planning.md](planning.md)。

```markdown
- 验证范围：本轮文件、章节或段落。
- 执行操作：实际工具/人工核对、输入和时间。
- 实际结果：通过/未通过/未运行，各自证据。
- 保真、证据支持、评审和检测：各项真实状态。
- 未解决项：位置、原因、影响与需要的资料。
- 下一步：已授权范围内的修订或依赖缺口。
```

报告的“通过”仅限已核验的对象，不将样稿检查推广为全部论文无问题。写作完成、代码配置验证、真实模型调用、实际 AI 检测和外部发表是不同声称，分别依据对应证据报告。
