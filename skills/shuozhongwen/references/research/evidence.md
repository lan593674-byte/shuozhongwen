# 证据驱动的引言、背景与相关工作

整合 evidence-driven-writing 与 literature-review 的证据门控。适用于含文献支持的引言、研究现状、背景、相关工作和综述；检索组织见 [literature.md](literature.md)。

## 先证据与蓝图，后正文

写这些章节前必须有可用证据映射和段落蓝图。持续项目保存 `refs/evidence-map.md` 或 `plan/evidence-map.md`、`plan/chapter-blueprints/<section>-blueprint.md` 和 `plan/review/evidence-coverage.md`。已有映射可更新而不重建空文件。

优先用户提供的文献池。只使用实际可见的题名、摘要、DOI 元数据、用户笔记/摘录或已读全文中的信息。题名只能支持主题信息，元数据只能证明身份信息；不能把元数据当技术发现，也不能把看过摘要表述成读过全文。

## 证据映射

```markdown
| Source ID | Citation | Source type/read level | Abstract-level finding | Usable fact | Supported claim | Citation slot | Risk |
|---|---|---|---|---|---|---|---|
| [ID] | [作者、年份、题名、出处、DOI/链接] | [全文/摘要/笔记/元数据] | [实际可见发现] | [可使用事实及条件] | [正文中可写的一句具体论点] | [章节-Pn-段落角色] | [direct/indirect/unverified] |
```

- 一个来源在一个引用位置必须支撑具体论点，不能只说“这篇很相关”或为泛泛领域陈述装饰引用。
- `Citation slot` 具体到段落角色，如 Introduction-P2 方法谱系。
- 核心论点至少有一条直接强支撑；关键研究空白尽量由两条以上相关独立来源共同支撑，来源不足时缩小或暂缓空白声称。
- 弱支持或跨范围推断标记 indirect。直接引用保留出处和定位；未知页码不补造。
- 不把同一数据集或相互引用的相近来源当独立重复证据。
- 重要资料未使用须记录原因；反例和矛盾证据不能因不利于结论而删掉。

## 段落蓝图

```markdown
### Paragraph N
- Role: context / method landscape / limitation / gap / contribution
- Main claim / 本段主张：
- Evidence IDs / 实际来源：
- Support boundary / 对象、条件、读到的证据层级：
- Contrast or transition / 与前后段的比较或承接：
- Forbidden content / 不允许的推断、过程说明与过强结论：
```

蓝图不是正文。完成后检查段落是否形成问题压力、方法路线、尚未解决的瓶颈、本文定位和贡献边界的论证链。没有可用来源的段落先记录缺口，不能先写“学界普遍认为”再补假引用。

## 技术引言的组织

通常由以下关系推进，按实际材料合并或调整段数：

1. 应用场景与问题为何值得研究，用基础或综述来源定位对象。
2. 按方法家族解释既有技术路线，说明各路线能解决什么。
3. 描述瓶颈递进：精度、成本、条件或泛化限制如何共同造成研究困难。
4. 给出本文方法实际能触及的具体空白，不把所有领域问题都归为本文贡献。
5. 引出设计选择与贡献，并说明验证或适用边界。

计算机/工程 SCI 引言可把相关工作综合嵌入上述动机链；不因旧稿存在 Related Work 就保留独立章。仅当目标大纲需要时单列。论文组织说明最多作为简短收束，不能替代研究空白论证。

## 相关工作的综合

每个主题段先界定方法家族或研究脉络，随后比较通常 2—4 个相关来源，再说明共同限制和下一主题或本文方法的必要性。没有足够来源时按可用证据写，不硬凑数量。

不能逐篇重复“作者—年份—方法—结论”。正文段落应至少综合两种内容：问题条件、方法家族、多研究共同局限、到本文方法的桥梁、带引用的边界。若一段能无损压成文献表的一行，通常还没有完成正文论证。

## 结构样例：由场景缩窄到设计

上游 GPR 示例可提炼为以下蓝图，借用关系而不移植其领域内容或未验证事实：

```markdown
P1 场景：某技术在多种真实应用中承担某任务。
证据：基础定义与代表应用。

P2 技术必要性：某子问题控制下游处理的性能或可行性。
证据：方法与下游任务文献。

P3 方法谱系：传统路线分为不同家族，各有条件与优势。
证据：同类方法的分组比较。

P4 瓶颈：目前较准确的路线在迭代成本或部署条件下受到限制。
证据：复杂度、运行时间或实验边界。

P5 新路线及其限制：新方法降低某成本，但尚未覆盖关键交互或泛化条件。
证据：实际读到的新方法结果与限制。

P6 本文定位：设计组件、数据与表示方式直接针对上述瓶颈。
证据：本文方法与验证计划；不能写成已经验证的收益。
```

## 证据覆盖复核

```markdown
| 段落/核心论点 | 来源 ID | 直接支持的部分 | 间接推断或缺口 | 处理 |
|---|---|---|---|---|
```

核对正文实际引用是否出现在映射中、引用内容是否在读到的证据内、空白是否有支撑、贡献是否与方法/实验对应。发现仅引用多而没有支持关系，仍判不通过。

正文污染防护：用户要求、写作提示、后续回填说明、任务包内容只能进计划。缩短时保留论点、证据、方法条件和限制，不以表格代替应有的论证。
