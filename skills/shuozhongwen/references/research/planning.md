# 写作规划与任务编排

适用于论文项目启动、章节任务、中型改稿、整篇重构和长期返修。整合 brainstorming-research、paper-orchestration、workflow-lifecycle、module-guide 与计划模板。所有路径都是当前论文项目内的产物路径，不是插件安装路径。

## 对齐任务而不过度追问

先读取用户材料、现有正文及 plan 中的概览、进度、笔记和大纲。提取论文类型、学科、题目、问题、研究背景与目的、方法、材料来源、目标读者、目标学校或期刊、语言、长度、格式和本轮范围。已提供或已确认的信息不重复问。

新项目先完成范围和结构对齐，再写正文。只问实际影响写作的缺口；自然地一次讨论一个关键问题，给推荐方案和理由，让用户确认或微调。不要让用户填完整表单，不强制七轮问答。已有文稿的一段改写无需重新设计全文。

默认毕业论文、中文期刊、中文课程任务使用中文，SCI/SSCI 或国际会议依目标要求使用英文；不为默认语言单独追问。用户语言要求和课程要求优先。默认 Markdown，明确要求或已选模板时输出 LaTeX。

结构由用户、目标体例和论文类型决定。用户已明确授权完整写作或连续改稿时，记录该授权并按章校核继续；不在每章结束后重复要求许可。尚未确定的结构或关键方法不能假装已确认。真正缺失的事实、数据与不可推断的选择，记录为缺口，只暂停依赖它的部分。

## 任务规模与前置产物

单次术语问答可直接回答。一次性短文改写依用户提供的用途和原文对齐，不强迫落盘一套空项目。持续论文项目维护 plan。中型任务指多段、多小节、任一完整章节、文献论证链、结果解释或反复质量返工，执行前必须留下可审计任务包。

中型与整篇任务至少准备：

- `plan/project-overview.md`：问题、方法、范围、材料、目标、格式与偏好。
- `plan/outline.md`：已对齐的章节目标和论证顺序。
- `plan/progress.md`：当前阶段、任务、验收记录与下一步。
- `plan/notes.md`：决策、用户授权、缺口、检索日志和特殊要求。
- `plan/task-packets/<task>.md`：本轮持久任务包。

完整初稿或重稿还建立 `plan/chapter-architecture.md`，锁定当前版本需要的章文件、作用、长度口径、负责者和占位政策。章数与最小长度按目标材料制定，不把示例值当所有论文的要求。

## 写作阶段路由

| 当前工作 | 下一步与参考 |

| S3 研究设置、数据、结果、讨论 | [results.md](results.md)，统计报告按 [statistics.md](statistics.md) |

记录当前阶段；阶段标签表示工作位置，不强制给已经完成的材料重新走一遍流程。

## 论文结构参考

以下是可调结构和篇幅参考，必须服从用户及目标规范。

| 类型 | 常见结构 | 常见总篇幅参考 |
|---|---|---|
| 本科毕业论文 | 摘要；绪论；理论基础或文献综述；研究设计与方法；实验/实证分析；结论与展望；参考文献；致谢 | 8000—15000 字 |
| 硕士论文 | 摘要；绪论；文献综述；研究方法；结果；讨论；结论；参考文献；致谢 | 20000—40000 字 |
| 博士论文 | 摘要；绪论；文献综述；研究框架与方法；研究结果；讨论；结论与未来研究；参考文献；附录；致谢 | 50000—100000 字 |
| 中文期刊 | 摘要；关键词；引言；材料与方法/设计；结果；讨论；结论；参考文献 | 5000—8000 字 |
| SCI/SSCI | Abstract；Keywords；Introduction；Methods；Results；Discussion；Conclusion；References | 3000—8000 词，按期刊 |
| 会议论文 | 摘要；引言；方法；结果/实验；讨论或并入结果；结论；参考文献 | 按页数和会议要求 |
| 课程论文 | 引言；概念/理论；案例或实证；讨论；结论；参考文献 | 3000—5000 字 |
| 开题报告 | 背景意义；研究现状；目标内容；方法路线；预期成果与创新；研究计划；参考文献 | 3000—5000 字 |

硕士论文可参考绪论 3000—5000 字、综述 5000—8000 字、方法 3000—5000 字、结果 5000—10000 字、讨论 3000—5000 字、结论 1500—2500 字；SCI 可参考引言 500—800 词、方法 800—1500 词、结果 1000—2000 词、讨论 1000—1500 词。这些是规划起点，不是自动验收阈值。

计算机/工程 SCI 论文优先让引言结合相关研究形成动机与空白论证，主体可按 Introduction → Methodology → Dataset and Experimental Setting → Experimental Results and Analysis → Discussion 组织，设置短时可并入方法或结果。仅在大纲或目标体例需要时独立 Related Work；不能用摘要、结论、参考文献数量遮盖薄弱主体。文科、法学及不同设计不机械套用该结构。

章文件通常使用两位数字前缀和稳定英文名，例如 `chapters/01-introduction.md`；中文文件名或既有命名明确可用时不强迫改名。Markdown/LaTeX 扩展名与实际输出一致。

```markdown
# 任务包
- Scope / 本轮范围：

- Files allowed to edit / 允许修改文件：
- Required references / 必读本参考库文档：
- Evidence/data inputs / 证据与数据：
- Required artifacts / 必要产物：
- Rejection checks / 拒收条件：
- Validation operations / 验证操作：
- 已有授权与需要确认的实际缺口：

## 章节任务附加项
- 独占负责章文件、在全文中的作用：
- 段落级论证链，而非只有节标题：
- 最小正文长度及统计口径：
- 必用来源、证据 ID、实验协议：
- 禁止措辞、禁止结构、占位政策：
- 交接格式：状态、文件、论证链、缺口、自审：
```

```markdown
# 章节架构
- chapters/01-introduction.md | role=动机与空白 | min_chars=[按目标填写] | owner=[负责者] | placeholders=no
- chapters/02-methods.md | role=可复现方法流 | min_chars=[按目标填写] | owner=[负责者] | placeholders=no
```

正文长度统计须说明中文字符或英文词数、是否排除标题/参考文献。架构中的必需章缺失、意外继承旧章、主体仅摘要级短稿均需返工；配套摘要、结论、参考文献也须在架构中说明。

完整论文初稿或重稿在子代理可用时，为每个主要章节派发独立的新代理，给该章任务包、必要资料摘录、证据映射、实验协议和拒收条件。各代理只编辑独占文件，控制者负责跨章一致性和最终评审。不能将同一文件派给多个代理。若环境不能派发，明确记录限制和独立章节写作/复核方式；不得伪造代理出处或把一次生成当成已完成独立复核。

`plan/chapter-agent-provenance.md` 记录负责者、任务包、提示摘要、输入、输出路径、返回状态与控制者复核结果。返回状态为 DONE、DONE_WITH_CONCERNS、NEEDS_CONTEXT 或 BLOCKED；这些不是最终验收，控制者确认后记录 ACCEPTED 或需返工。

## 两阶段复核和使用审计

每个中型任务和每章先做规范合规复核：对任务包、字数、结构、引用体例、标题、必需文件与用户约束。再做质量复核：证据是否支撑结论、论证连续、术语一致、数据保真、正文无过程说明、语言自然。任一未通过，修订后重新检查相应失败项再进入下个任务。

```markdown
# 本轮进度
- 当前阶段、任务、日期：
- 输入/输出文件与验收标准：
- 规范合规 review：通过/失败；证据与修改项：
- 质量 review：通过/失败；证据与修改项：
- 状态、长度、已授权范围、待确认缺口：

## Capability-use audit / 能力使用审计
- Required references / 应读参考：
- References actually used / 实际使用：
- Inputs consumed / 已使用资料：
- Inputs not used and why / 未用资料及原因：
- Artifacts produced / 产物：
- Verification run / 验证操作与结果：
- Remaining risk / 剩余风险：
```

## 长期项目与投稿材料

长期项目在 `plan/stage-gates.md` 记录：启动边界 → 研究方案/适用的注册 → 检索与纳排 → 证据综合 → 大纲方法 → 初稿 → 质量合规 → 投稿包 → 返修归档。完成一轮更新进度与关键决策，跳过不适用项注明原因。

系统综述维护检索式、日期、数据库、结果数、去重与筛选统计。预注册只形成真实计划和字段草稿，不宣称已注册。医学报告规范按 [medical.md](medical.md) 核查适用版本。

用户需要投稿材料时，可草拟 cover letter、作者贡献、利益冲突、伦理/数据共享声明与 AI 使用披露。只用实际作者、真实批准和数据共享事实；缺失信息留在计划中。`plan/submission-checklist.md` 核对长度、附件、文件名、盲审、元数据和引用体例，生成材料不自动授权外部投稿。

返修维护“审稿意见—响应矩阵”：逐条意见、接受/部分接受/不接受、理由、改动位置、支撑证据、状态。变更日志记录版本、日期、范围与仍未解决的问题，归档所需复现材料的实际位置。
