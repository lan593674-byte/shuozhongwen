# 章节写作与跨章一致性

用于实际章节起草和重稿。先读 [core.md](core.md)，持续项目按 [planning.md](planning.md) 对齐概览、大纲和本轮任务包。完整论文依据已锁定的章架构与负责者写作。

## 写作前

- 读取 `plan/project-overview.md`、`plan/outline.md`、`plan/progress.md`、`plan/notes.md`，确认本章作用、材料与相邻章依赖。
- 若有 `plan/chapter-architecture.md`，核对精确文件名、目标长度、正文口径、占位政策和独占负责者。
- 引言、相关工作、背景、综述先读 [evidence.md](evidence.md)，消化证据映射、段落蓝图与覆盖复核。
- 方法采用输入到输出论证；实验、结果和讨论先读 [results.md](results.md)，核对真实数据与允许结论。
- 学科选择 [humanities.md](humanities.md)、[medical.md](medical.md) 或 [law.md](law.md)，理工科以通用规则和真实方法材料为基础。

前置章未完成不自动禁止当前章：判断其是否真正影响术语、方法、数据和结论。已授权的独立部分继续，依赖缺口记录到笔记，不编造前置内容。

## 章节执行与交接

按蓝图写到本章文件，不能把标题清单标成完成。完整主体章应展开论证、方法条件与证据，达到章架构确定的长度；不足时扩写已有证据的解释或返回 NEEDS_CONTEXT，不用空话凑字数。

完整初稿或重稿的主要章节由独立新代理负责时，控制者提供章任务包、读哪些资料、改哪个文件、本章作用、段落关系、最小长度、禁止结构和拒收条件；见 [planning.md](planning.md)。代理返回：

```markdown
- Status: DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED
- Changed file:
- Argument chain:
- Unresolved evidence/data gaps:
- Self-review against rejection checks:
```

控制者检查后记录 provenance 与验收，不把代理的“DONE”当成独立完成证据。不能多个代理同时修改同一章节。

## 连续论证而非罗列

| 段落用途 | 必须形成的关系 |
|---|---|
| 背景 | 场景约束 → 研究矛盾 → 本章承接 |
| 文献 | 同类研究解决的问题 → 代表证据的比较 → 未覆盖边界 |
| 方法 | 输入对象 → 处理过程 → 输出形式 → 设计理由 |
| 实验 | 评价目标 → 对照关系 → 指标含义 → 可接受结论边界 |
| 讨论 | 结果含义 → 技术/理论解释 → 局限与后续验证 |

这些关系是写作检查标准，不直接作为每段相同的句式。段落必须体现因果、比较、承接、限定或转折；不得将这些检查词和箭头写进论文。正文默认连续段落，贡献列表仅在目标体例允许时少量使用，并有上下文解释。

## 摘要

正文稳定后写摘要，按背景、目的、方法、主要结果和结论覆盖实质内容；目标期刊要求结构标签时采用标签。中文通常可参考 300—500 字，英文 150—300 词，具体按学校或期刊。不能以结构模板替代真实结果。

摘要不含引用和图表；没有要求时不加入新术语和正文未出现的发现。中英文摘要的数据、对象、方法与结论一一对应。缺真实结果时只能交付明确状态的草稿，不写预测结果为已发生发现。

## 引言或绪论

交代背景、现有不足、研究问题、目标、方法概述及贡献边界。绪论可含研究内容和简短结构安排；结构介绍不替代空白论证。引言涉及研究现状时，按证据映射综合方法路线，避免泛泛“随着技术发展”开头。学位论文较完整绪论与期刊较短引言的功能不同，依论文类型调整。

## 文献综述

使用 [literature.md](literature.md)，按主题、学派、方法或合理时间脉络组织；有分析、贡献、局限、不同研究的支持/补充/矛盾关系和本研究定位。不能只把文献笔记串联。仅依摘要时限制结论强度，注明阅读范围到计划，不假装全文细读。

## 方法：输入到输出

1. 输入：数据形态、样本、特征、研究对象和约束。
2. 预处理或表示：清洗、纳排、编码、划分、标准化；说明对象与参数来源。
3. 核心模型/程序：每个组件的输入、处理、输出和设计理由。
4. 训练、推理或分析：公式、算法、参数更新、决策路径及可复现步骤。
5. 输出：预测、解释、诊断、指标或下游接口的形式。
6. 与验证对应：每个关键设计能指向对照、消融、分析或明确局限。

“包括三层/若干模块”必须继续说明实际数据流和设计联系；不能只列模块名。公式定义符号、单位、范围、条件与使用位置；用户未给的算法机制不猜造。人文/法学方法可用材料到分析结论的逻辑流，而非硬套机器学习训练。

## 结果与分析

依据 [results.md](results.md) 先锁实验协议、方法—实验追踪、表格字段与数据来源，再写评价目标、公平对照、指标含义、实际比较和允许边界。正文不是数据报账，也不能超越原始结果。

真实结果用数字和条件支撑；无明显优势、失败案例、阴性结果都如实报告。模拟值只作为被明确要求的规划数据，保留 `[待真实实验替换]`，不写“实验结果表明”或已验证。最终正文不能含“实验目的”“表位”“回填模板”“讨论提示”“请用户替换”等工作流说明。

## 讨论

解释结果为何重要、与文献何处一致/不同、何种机制有证据、什么仍只是可能解释。指出对象、样本、方法、数据、统计功效、部署或外推限制。结果未支持的机制和因果断言收束为有边界的解释；未来工作不冒充已完成实验。

## 结论

回应研究目的，概括实际发现和贡献，明确局限及未来方向。不给未经正文论证的新结论、新证据或新实验；不简单复制摘要，不空泛拔高应用意义。

## 正文污染检查

用户修改要求、写作提示、任务包、检查清单、回填指导和过程说明不能进入正文或附录。保留数据缺口标记不意味着可以粘贴长段计划说明。表格支撑论证而不取代正文，压缩保留论点、证据、条件和边界。

## 每章两阶段验收

规范合规：字数是否符合已定范围（可参考 ±10%，不能覆盖硬性上限）、结构和标题是否满足大纲、引用是否采用指定体例、必需文件是否齐全。

质量：证据与结论匹配、方法可复现、数据和术语保真、句子自然、段落连续、无模板堆砌与正文污染。两阶段失败都先修订。记录实际长度、状态、未解决项、验证及授权到 `plan/progress.md`；需要用户确认的内容与已授权连续执行的任务分开记录，不重复询问后者。
