# 实验规划、数据契约与结果写作

整合 experiment-results-planning 的写作部分与实验分析提示。指导实验结果的组织、追踪和表述，不自动执行实验、绘图或生成假数据。统计报告另读 [statistics.md](statistics.md)。

## 结果写作前的产物

仅在新写、规划或实质重构实验结果/讨论时建立以下产物；已有契约直接读取并更新。对已有结果段的纯语言润色、翻译或不改变研究的局部改稿，只读取实际数据与上下文、执行局部保真，不为这次短任务创建整套实验工程。需要重新论证贡献或补充结果来源时才进入本节前置流程。

进入结果规划或实质写作时，先形成：

- `plan/experiment-protocol.md`：实际或已锁定的研究/实验设置。
- `plan/review/method-experiment-traceability.md`：贡献—方法—实验—表/材料—允许结论。
- `tables/table-schema.md`：各表目的、字段、数据与聚合口径。
- `plan/result-data-manifest.md`：原始数据/日志、来源、状态、聚合、正文位置。
- 真实结果文件，或用户明确需要且标示边界的规划数据文件。

这里用结果数据清单承接上游 figure data manifest 的数据溯源规则；用户已有图表时将其数据与图注纳入清单，不增加绘图脚本或绘图命令。

## 实验协议

按研究实际记录数据集/样本版本、来源、纳排、训练/验证/测试划分及理由；基线选择与公平性；指标定义、方向、单位、类别不平衡处理；主要比较；重复、随机种子、实际软硬件及日志字段。Non-IID 构造仅在实际研究涉及时记录。

效率评价说明同条件耗时、内存、算力或开销口径。声称模块贡献需要对应消融；泛化/鲁棒性声称需要对象、跨数据/跨条件或扰动验证。XAI 作为贡献时需要解释的稳定性、开销和领域一致性证据。不是每篇论文都强制拥有这些结果族：未适用注明原因，未验证的贡献收束为限制或未来工作。

## 贡献追踪与表格契约

```markdown
| Contribution | Method module | Experiment/analysis | Table/figure/material | Allowed claim | Evidence status |
|---|---|---|---|---|---|
```

引言每个贡献映射到实际实验/分析或限制。不能用没有结果的贡献保持宣传性表述。

```markdown
| Table | Purpose/支持论点 | Rows/对照对象 | Metrics/单位与方向 | Data source | Aggregation/repeats | Replacement owner/status |
|---|---|---|---|---|---|---|
```

只创建能支持论文论点的表。重复实验适用时提供 mean ± SD 或置信区间，说明聚合对象、重复数、排除规则和区间算法；不能把 SD、SE、CI 混用。表格中的百分比、百分点评估和分母必须明确。

```markdown
| 数据/日志文件 | 来源与日期/版本 | real/mock/synthetic | 条件与样本 | 聚合规则 | 对应表/图/段落 | 尚缺内容 |
|---|---|---|---|---|---|---|
```

## 数据保真与模拟边界

保留输入数字、单位、组别、基线、指标、时间、样本和结论条件。改写不是重新估计数据；涉及算术转换时显示实际算法、单位和核验结果。无明显优势或趋势时如实描述，不夸大提升，不捏造失败现象。

mock/synthetic 只允许用于用户要求的表格布局或结果段结构规划，不能替代真实实验：

- 文件名用 `mock_` 或 `synthetic_` 前缀。
- 表及相关文件带 `PLANNING DATA - replace before submission`。
- 引用模拟值的草稿段保留 `[待真实实验替换]`。
- 不能把这些值称为 results show、实验结果表明、verified 或已验证。
- 最终稿与投稿稿去除未回填模拟数据和占位；若真实结果仍缺，明确未达到定稿状态。

真实结果与规划数据可以同时存在于项目，但必须逐项绑定来源和允许声称；不能因某个规划文件存在就否定全部真实结果，也不能用真实一项掩盖模拟另一项。

## 结果段落

真实结果段按评价目标、条件、对照、指标变化、可支持的解释和仍存在的问题组织：

```text
在条件 Y 下，方法在指标 M 上达到 X，与同条件基线 Z 比较为 [真实差异及口径]。
消融/辅助结果 [证据位置] 支持该变化与 [模块] 的联系；[实际失败条件] 仍受到 [指标] 限制。
```

没有消融证据不能直接归因某模块，没有显著性检验不能把“显著”当统计结论。不要逐格报账“A 为 0.5，B 为 0.6”；解释真实比较、变化趋势、参数敏感性、性能—效率取舍、消融贡献和限制。

英文 LaTeX 分析可按目标体例使用 `\paragraph{核心结论}` 加连续分析文本，并给中文直译。段标题应是实际论点，不是“实验目的/讨论提示”。只有目标允许时使用该命令，正文不加粗、斜体或列表堆叠。

## 讨论与图表文字

讨论区分数据支持结论、文献比较、可能机制与未来验证。阴性结果不解释为已证明无效，应考虑区间、设计和功效。图表已有时，图注写清测量对象、条件、样本/重复、指标、单位、误差定义和符号，不写作者希望它证明什么。

图/表标题的英文名词短语按目标采用 Title Case，完整句子用 sentence case；删除“The figure shows/This diagram illustrates”等空转开头。表题可用 Comparison with、Ablation Study on、Results on 等准确名称，不以 showcase/depict 作装饰。标题是否含编号、句末句点按目标体例，生成标题文字时不重复自动编号。

## 结果阶段验收

| Gate | 必需检查 |
|---|---|
| D0 协议锁定 | 数据/样本、划分、基线、指标、重复、环境与日志字段实际可追踪 |
| D1 方法—实验追踪 | 每个贡献有验证或限制，允许结论明确 |
| D2 数据契约 | 表字段、清单、来源和聚合规则齐全，真实/规划状态可区分 |
| D3 结果族回填 | 适用的主比较、效率、消融、泛化/XAI 有数据、表格和正文；未适用注明 |
| D4 正文去污染 | 无实验目的、表位、回填模板、讨论提示或请用户替换等过程语言 |
| D5 评审 | 复现、公平对照、声称支撑、结果完整、表图口径通过 [peer-review.md](peer-review.md) |

记录真实缺口和完成状态，不以完整表格外观替代实验完成证据。
